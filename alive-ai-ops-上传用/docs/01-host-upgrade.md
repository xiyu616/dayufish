# 坑 1：宿主客户端一升级，你这边的桥接就哑了

## 现象

早上八点，该发的东西没发。人不在电脑前，什么都不知道。
晚上打开电脑：网关进程在跑，日志里一片安静，但一条消息都发不出去。

## 真实经过

我用的是一个第三方协议端把 QQ 桥接给 AI。某天它背后的项目收到律师函、宣布转私有，
不再公开维护。这事本身不影响已经跑起来的实例 —— 真正的断点是另一个东西：

**它绑的是宿主客户端的原生模块。宿主客户端一自动升级，原生绑定对不上，整个桥接立刻哑。**

我去找"关闭自动更新"的开关。结论：**Windows 版 NTQQ 没有这个开关。**
设置页翻过、`Ctrl+,` 试过、右键菜单也翻过。没有。它想升就升。

## 排查路径（下次照这个顺序）

1. **先确认是"通道死"还是"AI 死"**。直接打协议端的 HTTP 接口：
   ```powershell
   Invoke-RestMethod -Uri "http://127.0.0.1:3000/get_login_info" -Headers @{ Authorization = "Bearer <token>" }
   ```
2. **返回 401 不等于挂了**。401 是"服务活着，你没带对凭证"。我第一次排查就栽在这：
   以为是通道挂了，其实是换了 token 没更新。
3. **看宿主客户端的版本目录**。里面会多出一个新版号目录，说明它已经升完了。
4. **看有没有下载好但没装的包**（`*.zip`）。有就说明下一次启动就会升。

## 解法：别堵升级，保证能退回去

堵不住的。所以做三件事：

### 1) 备份要连宿主一起备

只备份你自己写的程序没用。要备份：

- 你的网关整包（自包含发行包最省事，连 node 都内置）
- **宿主客户端的当前版本目录**（我这边 1GB，别嫌大）
- 宿主版本目录里的 `config.json`（版本指针就在里面）

### 2) 拦截安装包

定时扫版本目录，把 `*.zip` 改成 `*.zip.disabled`。它下载了也装不上：

```powershell
Get-ChildItem $versions -Filter "*.zip" -File | ForEach-Object {
    Rename-Item $_.FullName ($_.FullName + ".disabled")
}
```

完整版见 `scripts/version-guard.ps1`，建议每 6 小时跑一次。

### 3) 真被升了要能回退

`scripts/revert-host.ps1` 干四件事：备份配置 → 缺目录就从备份拷 → 把版本指针指回去 → 作废残留安装包。

**先跑 `-DryRun` 看它要干什么**，别一上来就真动。

## 踩过的坑（省你半小时）

- `Register-ScheduledTask` 里用 `[TimeSpan]::MaxValue` 当重复间隔会报 XML 越界
  （`P99999999DT...`）。改用 `[TimeSpan]::FromDays(3650)` 就行。
- 回退脚本必须**先检查进程**。宿主还在跑的时候改版本号，改完它自己又给写回去了。
- 备份完别只测"文件在不在"，要测**能不能用备份启动一次**。没验证过的备份等于没有。

## 一句话教训

**自动升级堵不住，但可以保证"升坏了能十分钟退回去"。** 这才是可运维。
