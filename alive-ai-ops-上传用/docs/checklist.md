# 上手清单：从零搭一个能常驻的 AI

按顺序做。每一步都有"做完怎么验证"，别跳过验证 —— 没验证过等于没做。

## 第 0 步：先想清楚它要干嘛

- [ ] 它常驻在哪？（QQ / 微信 / 网页 / 只本机）
- [ ] 它每天固定要做什么？（报信息 / 定时检查 / 回消息）
- [ ] 它坏了，谁能发现？（如果答案是"我"，那它一定会坏很久才被发现）

## 第 1 步：通道能跑通

- [ ] 宿主客户端 + 协议端 + 你的桥接，三层都起来
- [ ] 手动发一条消息，能从任意一端到另一端
- [ ] **验证**：关掉桥接再重开，还能发。不是"能发一次"，是"重启后还能发"

## 第 2 步：把凭证拿出去

- [ ] token / 密码不要写死在脚本里
- [ ] 放一个单独的文本文件里，权限收紧（别的用户读不到）
- [ ] **验证**：`Get-Content token文件` 能读到；脚本里没有明文

## 第 3 步：备份（在它跑通的第一天就做，别等出事）

- [ ] 你的程序整包
- [ ] **宿主客户端的当前版本目录**（这一条最多人漏）
- [ ] 宿主版本目录里的配置文件
- [ ] **验证**：把备份拷到另一个目录，真启动一次。启动不了就重做

## 第 4 步：探活

- [ ] 每 5 分钟打一次真实接口（不是看进程）
- [ ] 失败计数落盘（脚本重启后还能接着数）
- [ ] **验证**：手动把服务停掉，等 10 分钟，看日志有没有连续失败记录

## 第 5 步：自动拉起 + 喊人

- [ ] 连续 2 次失败 → 拉起一次
- [ ] 连续 3 次失败 → 弹窗 + 提示音
- [ ] 每个周期最多重启 2 次
- [ ] **验证**：停掉服务，等 15 分钟，看它有没有自己起来；不行就看有没有弹窗

## 第 6 步：拦截宿主升级

- [ ] 定时扫版本目录，`*.zip` 全部 `.disabled`
- [ ] 每 6 小时一次
- [ ] **验证**：手动往目录里扔一个假 zip，等一轮，看有没有被改名

## 第 7 步：回退脚本

- [ ] 支持 `-DryRun`
- [ ] 先检查进程（宿主在跑就不能改版本号）
- [ ] **验证**：跑 DryRun，输出跟你预期一致

## 第 8 步：定时任务设置

- [ ] `StartWhenAvailable = $true`
- [ ] 关掉 `DisallowStartIfOnBatteries` 和 `StopIfGoingOnBatteries`
- [ ] 任务跑的脚本**内部**再判断一次时间闸
- [ ] **验证**：把系统时间往后调 / 关机错过一次，看补跑时行为对不对

## 第 9 步：记忆

- [ ] 轻量记忆（当前话题、对谁的印象）
- [ ] 时间线（决定、事故、约定）
- [ ] 每天一条反思
- [ ] **验证**：隔一天问它"昨天我们定了什么"，看能不能答上来

## 第 10 步：让它自己会看日志

- [ ] 日志按日期分文件或定期归档
- [ ] 正常日志降噪（别 288 行"正常"）
- [ ] 异常必写、恢复必写
- [ ] **验证**：翻一个月前的日志，能不能在 1 分钟内找到那天出过什么事

---

## 反面清单（这些我都做过，别做）

- ❌ 用"进程还在"判断"活着"
- ❌ 备份了但没试过恢复
- ❌ 脚本没有时间闸
- ❌ 重型子进程挂在主进程树下
- ❌ 同类结论往记忆里堆五遍
- ❌ 只备份自己的程序，不备份宿主
- ❌ 出事了才想起来没日志
