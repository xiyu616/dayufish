# 从零开始：一个周末让它跑起来

前面五篇讲的是"为什么"，这篇讲"怎么做"。按顺序做，每一步都有验收标准。

## 你需要的东西

- 一台能长期开着的 Windows 机器（4G 内存就够，不用显卡）
- 一个愿意让它挂着的聊天账号
- 一个模型 API（有 key，能调）
- 两天空闲。真的，别想着一小时搞定

不用 Docker，不用云服务器。这台机器上出的问题，你都能亲手修。

## 周六上午：把通道打通

**目标：你说一句话，它能收到；它说一句，你能看到。**

1. 装宿主客户端（QQ 就装 QQ），登录那个账号
2. 装协议端（把 QQ 的消息转成 HTTP/WebSocket 的那一层）
3. 配好 OneBot：HTTP 端口 3000，WS 端口 3001，**记下 access token**
4. 写一个最小的桥接：收消息 → 调模型 → 回消息

先只做"收到就回一句"，不要加任何工具、任何记忆、任何人设。

**验收**：关掉桥接再重开，还能正常收发。
只测通一次不算数 —— 重启后失效是最常见的坑，早点撞见比晚点撞见好。

## 周六下午：让它别死

这一步大多数人不做，然后在第一周就吃了亏。

1. 把凭证从代码里挪出去（单独文件，权限收紧）
2. 写探活脚本：每 5 分钟打一次真实接口，**不是看进程在不在**
3. 连续 2 次失败 → 自动拉起；连续 3 次 → 弹窗喊人
4. 注册成计划任务，顺手打开 `StartWhenAvailable`
5. 备份宿主客户端的版本目录（不是只备份你自己的代码）

细节都在 [坑 1](01-host-upgrade.md) 和 [坑 2](02-silent-death.md)。脚本直接用 `scripts/health-check.ps1`。

**验收**：手动停掉服务，十五分钟内它自己起来；起不来的时候你能收到提示。
（测这个最好挑白天，别在睡前测。）

## 周日上午：让它记事

**目标：隔一天问它"昨天我们定了什么"，它能答上来。**

三层就够，别搞复杂：

1. **轻量记忆**：正在聊什么、对谁有什么印象。每次醒来读。过期就删
2. **时间线**：有影响的事 —— 决定、事故、约定、状态变化。需要上下文时读
3. **日记/反思**：每天一条，压成两三句判断。不常读，但它是明天的它看的东西

硬规矩只有三条：

- 同类结论**覆盖**旧的，不要往上堆
- 记**证据**，不记形容词
- 过期的主动删

细节见 [坑 5](05-burn-and-memory.md)。

**验收**：隔一天问它昨天的事。答不上来，说明你只是把记忆写进了文件，没让它读。

## 周日下午：省钱

- 每天固定要做的事，交给计划任务，结果落盘，会话里只读结论
- 一次工具调用能查完的，别分三次
- 需要"看"的东西先抽帧/抽字幕，别把整个视频塞进去
- 长期不变的信息写进文件，别每轮贴

**验收**：翻一下昨天的用量，问自己"这里面有多少是它重复发现自己昨天已知的事"。

## 周日晚上：留一条后路

1. 写清楚"出事怎么救"的一页纸，放在显眼的地方（比如桌面）
2. 里面要有：怎么判断是通道挂了还是模型挂了、怎么回退版本、找谁
3. **真的模拟一次**：把服务停掉，按你自己写的步骤救回来

没法执行的应急预案等于没有。这一条我吃了亏 —— 备份过，没试过恢复，出事那天才发现少一个文件。

## 常见死法（按我踩的顺序）

| 症状 | 真相 | 修法 |
| --- | --- | --- |
| 进程在，消息发不出 | 探活用错了判断标准 | 打真实接口，别数进程 |
| 早上该报的没报 | 计划任务错过就跳过 | `StartWhenAvailable` + 脚本内部时间闸 |
| 突然全部失联 | 宿主客户端自动升级了 | 备份版本目录 + 回退脚本 |
| 整台机器卡死 | 重型子进程挂在主进程树下 | detached，或者干脆拆到另一台机器 |
| 账单吓人 | 每轮都在重算昨天已知的东西 | 落盘 + 计划任务 |

## 最后一句

搭这个东西的难点，从来不是"让它聪明"。是让它**明天还在**。

聪明是一次性的，在线是每天都要重新赢的。
